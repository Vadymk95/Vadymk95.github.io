Case study

What the gate caught

One quality gate, run by a person and by a coding agent, and the defects it found behind a green build.

The facts on this page come from four public templates, read on 9 October 2026: template-1 (React), template-spa-pwa (React PWA), template-next-seo (Next.js) and template-rn (React Native).

The problem

A small team now writes a good share of its frontend with AI tools. The code arrives faster than anyone can read it, the build stays green, and the defects show up in production: a layout that scrolls sideways on a phone, a button too small to tap, a test that passes without checking anything.

What the setup is

One gate for a person and for a coding agent, tiered by moment so an edit costs seconds and the full chain runs once.

Moment What runs Cost
While editing verify:iter Lint, type-check, the tests the change reaches Seconds
Before push verify:push Dependency audit, hook check, lint, format check, type-check, tests with coverage 12.3 to 29.2 s
CI, required check ci.yml The full chain, never shortened: the push checks plus the build, bundle budgets and end-to-end tests where the template has them Every push and pull request
Security security.yml Gitleaks secret scan; CodeQL on public repos Every push and pull request, and weekly
Weekly, Mondays 06:00 UTC mutation.yml Stryker mutation run: are the tests actually checking anything Minutes, off the critical path

The three web templates keep the build, bundle budgets and end-to-end tests out of the push until the first deploy, and CI runs them from day one. The push cost is the range over the last five passing pushes of each template, taken from the git-ignored trace log that every gate run writes on the author's machine.

Agent instruction files (AGENTS.md, with CLAUDE.md as a pointer) state the commands and the boundaries: what an agent must never touch, and which gate proves a change.

What it caught

The first run of the rendering checks in template-1 found 272 violations behind a green build, zero after the fixes (the fix commit). The classes, with what was measured:

Defect Measured
Header row could neither wrap nor shrink The page scrolled sideways by 28 px at 390 px width, on every route
Body text without overflow-wrap A 40-character token overflowed a 292 px column by 172 px, only at 390 px
Button row with whitespace-nowrap and no min-w-0 1,161 px of content in a 798 px container at 1,440 px
Header links with no touch height 39.5×20 px tap targets, below the 24 px minimum of WCAG 2.5.8, on every route and width
focus-visible:outline-none under Tailwind v4 In forced-colours mode both outline and box-shadow computed to none: keyboard focus was invisible

Mutation testing adds the layer coverage cannot: Stryker changes the code and expects a test to fail. The weekly run fails below a per-template floor (break at 40 percent in template-1 and template-spa-pwa, 35 in template-next-seo and 48 in template-rn, set in each stryker.config.json), so a suite that runs the code without checking it cannot quietly pass.

What a team gets in one week

  1. A read of one frontend repo: how the team uses AI tools, what the build checks today, where it is blind.
  2. The gate installed and adapted to the stack, with baselines for existing debt (a ratchet: no new violations, old ones fixed over time), never a "green from day one" demand a legacy repo cannot meet.
  3. An agent instruction file with the team's real commands and boundaries.
  4. A short written report: what was found, what now fails the build, what is left for later.

What it does not do

  • It does not make an AI tool smarter. A 2026 controlled study of 288 runs with Claude Code and Codex found that instruction files do not measurably change correctness (arXiv 2607.27250). The gates are what stop the wrong code.
  • Hooks are code that runs on the developer's machine, so the team reads every one before it goes in. In February 2026 Check Point published a Claude Code flaw where a malicious project hook ran commands when a developer opened an untrusted repository; it was patched before publication (Check Point Research).
  • Frontend only.
